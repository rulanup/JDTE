# Generator remote concurrency acceptance

Two separate graphical clients (`JDTEOne`, `JDTETwo`) simultaneously connect to a real loopback Forge 47.4.10 dedicated server with JDT 1.1.4, GuideME, AE2, Curios, JEI, Jade and ModernFix. Existing launch/filter/Xorg infrastructure is reused. Both clients and two consecutive server processes exit 0. [Run summary](run-summary.txt), [seed marker](seed-success), [restart marker](restart-success), expected saved NBT and two screenshots are retained.

The clients race a shared coal stack, return it, repeat Shift installation of Generator Upgrade, concurrently paste a source configuration, race a real Refined Fuel bucket and bag-panel upgrade installation, and reconnect after one disconnects with a nonempty cursor. The server concurrently exercises real item round-trip, output-only FE extraction and fluid drain/invalid-input paths with menus open. Assertions retain exactly 64 coal, one fuel bucket and five Generator Upgrades across players/bags/machines/cursors/drops. Both machines retain all remaining FE and fluid; the probe separately records 74 FE and seven mB extracted through the real interfaces. No fuel generation is expected while paused by redstone. High-bit FE and tank amounts synchronize to both clients.

After actual reconnect and natural pickup of the logout drop, both players disconnect. An observed real chunk unload is followed by saved shutdown. A new server JVM restores exact machine/player state; both original independent client JVMs reconnect and reopen their solid/fluid menus. Source recipes/global AE jobs and prolonged concurrency are outside this acceptance. [Failed attempts and corrections](failures.txt) are recorded, not counted as passes.
