# Live Bio Extractor independent-client concurrency

Pinned source JDTE 0.6.5.2; Forge 47.4.10 / JDT 1.1.4 / Java17; version 0.5.8. Two separate graphical client JVMs (`JDTEOne`, `JDTETwo`) connect simultaneously to a real dedicated server. Both clients and both consecutive server JVMs exit 0. [Run summary](run-summary.txt), complete server logs, NBT, markers and final screenshots are retained.

Both players operate the same Advanced machine, then the same Extended machine, while real natural world ticks harvest newly arriving cows and blue sheep. They repeatedly Shift-extract shared output and race filter-card installation/removal. Automatic output to real chests is enabled while menus remain open. A real Forge port extracts exactly 13 mB milk; the fixture keeps that external holding in its ledger. Every server tick verifies FE = 15,000,000 − 5,000 × cow operations − 3,000 × sheep operations, total milk plus external holding = 1,000 × cow operations, blue wool = 2 × sheep operations, and exactly four filter cards across live/disconnected players, menus, machines, chests and drops. Operations are observed from each creature's persistent shared cooldown changes, so overlapping extractors cannot silently double-charge or duplicate products.

Final successful ledger: **24 cow operations / 22 sheep operations / 13 external mB / 44 blue wool**, with exact FE and milk conservation. One client disconnects/rejoins while production continues. After both reconnect, creatures are moved to a safe holding pen outside the work area for an exact checkpoint. **No redstone production pause is used.** Fixture entity cramming is disabled to isolate shared-machine/resource behavior rather than unrelated herd suffocation. Prior failed worlds are preserved; each seed gets a new named disposable world.

Both players disconnect; real source chunk unload precedes saved shutdown. A fresh server JVM restores exact machine buffers/filters/cards/config, both player inventories and persisted creature cooldowns. Both original client JVMs reconnect and reopen the Advanced menu, comparing FE/milk exactly to the server checkpoint. [Failure chronology](failures.txt) records real bugs and fixture fixes. This is bounded live-production concurrency acceptance, not prolonged multiplayer certification. Separate Bio production evidence covers full-inventory wrench/placement and minimal optional-absence runtime.
