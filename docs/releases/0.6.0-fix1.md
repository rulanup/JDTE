# JDT Extras 0.6.0-fix1

Released September 25, 2026. This is the first hotfix release for the 0.6.0 line, for Minecraft 1.21.1, NeoForge 21.1.216+, Just Dire Things 1.5.7+, and Java 21.

## Compatibility and installation

| Component | Requirement |
| --- | --- |
| Minecraft | 1.21.1 |
| Mod loader | NeoForge 21.1.216 or newer |
| Just Dire Things | 1.5.7 or newer |
| Java | 21 |

Install the matching `jdte-0.6.0-fix1.jar` on the client and server. The optional full-grid addon is `jdte-ae-0.6.0-fix1.jar`; install matching JDTE and JDTE-AE versions on both sides when using full-grid AE2 acceleration. The `-sources.jar` files are for development and are not placed in the mods folder.

Upgrading from 0.6.0 requires no configuration or world changes; machine settings and block entities carry over unchanged.

## Highlights

### Greenhouse JEI performance

`BotanyPotsGreenhouseIntegration.getCrops` re-resolved every loaded Botany Pots crop on every call, and JEI calls it on every rebuild — each world join, each `/reload`, and some JEI setting changes. In large modpacks this stalled the loading screen repeatedly. The enumeration is now cached per RecipeManager instance (held through a weak reference) and invalidated on client recipe sync (`RecipesUpdatedEvent`), server datapack sync, client level unload, and server stop: cross-world and `/reload` cases always recompute, while unchanged recipes reuse the cached list.

The custom-crop fallback no longer rescans the whole item registry per crop. For each Soil recipe, every registered item the soil accepts is scanned once and memoized in registry order; each crop then only evaluates `crop.isGrowthSustained` over that list. The soil-order × item-order first-match result is identical to the previous behavior. The memo assumes soil matching never depends on the seed item, which holds for vanilla Botany Pots soils, and it is shared with the greenhouse planting path (`find`), so inserting custom-crop seeds into a greenhouse also skips the registry-wide scan.

### Fixed — Draconic Evolution stabilized spawner interception

Draconic Evolution is a compile-only dependency, and the `StabilizedSpawnerLogic` tile accessor previously declared `Object` as the return type. Mixin `@Accessor` matching is descriptor-exact, so the accessor found no `tile` candidate, the mixin failed to apply, and placing a Bio Crusher above a stabilized spawner crashed. The accessor now declares the exact `TileStabilizedSpawner` type, the `SpawnerMixin$DraconicSpawnerMixin` interception is registered in `mixins.jdte.json`, reflective tier lookup falls back to the default spawn count on any version mismatch, and a contract test pins the mixin registration.

### Easter egg artwork

The hidden client-only `2i` easter egg now ships its final 512x512 slot artwork through `EasterEggMipmapTexture`, which builds a CPU mip chain (512→16) with trilinear filtering so the texture stays smooth at slot scale instead of aliasing. Slot borders, player inventory squares, and inactive filter slots keep the vanilla look, as in 0.6.0.
