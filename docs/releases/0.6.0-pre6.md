# JDT Extras 0.6.0-pre6

Released September 9, 2026. This prerelease focuses on machine stability, automation compatibility, JEI loading and reloads, and more precise Time Multitool input.

## Compatibility and installation

| Component | Requirement |
| --- | --- |
| Minecraft | 1.21.1 |
| Mod loader | NeoForge 21.1.216 or newer |
| Just Dire Things | 1.5.7 or newer |
| Java | 21 |

Replace your existing JDTE JAR with `jdte-0.6.0-pre6.jar` on the client and server. Install only one JDTE version at a time. The `-sources.jar` is for development, not the mods folder. Existing block IDs, item IDs, and saved configuration keys are retained.

## Crashes and machine data

### Generator Upgrade crash — [#13](https://github.com/rulanup/JDTE/issues/13)

Installing a Generator Upgrade could make a running coal generator crash when it next consumed fuel. The transformed JDT class tried to load a helper from JDTE's reserved Mixin package, which Mixin rejects with `IllegalClassLoadError`.

The helper now resides in the normal runtime item package and exposes the methods required by the transformed generator. The upgrade still consumes two ordinary fuel items for three times the generated energy. The regression test executes the transformed `doBurn` path and checks actual fuel consumption and pending FE.

### Extended Energy Transmitter crash — [#17](https://github.com/rulanup/JDTE/issues/17), [#20](https://github.com/rulanup/JDTE/issues/20)

The JDT transmitter includes its own position in its energy network. For the extended block, JDT's lookup accepted only the original JDT block ID, leaving a null capability cache that crashed on the first active tick.

The extended transmitter now resolves its own position directly to its internal energy storage. Removed or non-transmitter targets return no handler before entering JDT's cache path. Other valid JDT transmitter lookups retain the original behavior; this fix does not replace the machine with the separate Advanced Energy Transmitter.

### Machine settings lost on breaking — [#11](https://github.com/rulanup/JDTE/issues/11)

Normal machine drops previously discarded the entire JDT custom-data component. This erased stored experience, speed, offsets, and other native settings when the dropped machine was placed again.

Drops now retain machine settings and persistent resources. Only known inventory and upgrade data that `onRemove` drops separately is removed from the block item, preventing duplicate contents. This includes the Factory Packer package slot. Energy, fluids, filters, Auto I/O configuration, and unknown NBT fields remain available to the normal restoration path. Values already lost in an older version cannot be reconstructed by the update.

## Loot Fabricator stability and JEI

### Reuse fake players — [#19](https://github.com/rulanup/JDTE/issues/19)

Every loot roll previously created a new fake player with a random identity. Mods that retain player connection handlers, such as the reported badpackets setup, could accumulate these objects throughout continuous production.

Loot rolls now use NeoForge's `FakePlayerFactory` with one stable, dedicated JDTE profile per server level. Machines do not borrow their owner's player identity. The temporary Looting weapon is cleared in `finally`, and NeoForge clears its factory cache when the level unloads. This bounds fake-player creation during production to the loaded dimensions that use the machine.

### Refresh previews from live loot tables — [#16](https://github.com/rulanup/JDTE/issues/16)

The machine already rolled the current server loot table, but its JEI preview parsed the original resource JSON. LootJS could change the compiled table while JEI continued to show the original drops.

Login and datapack synchronization now build the preview from the live loot registry using public codecs. Run `/reload` after editing LootJS table entries. Nested table edits and removed entries are included, and an empty live table does not restore the original JSON drops. Shared tables are encoded once per synchronization, with no encoded snapshot retained across reloads. Nested number providers are read defensively so they cannot abort synchronization.

The client replaces outdated visible JEI recipes while preserving their recipe IDs. Static previews cannot fully represent arbitrary callbacks or global loot modifiers executed only during a loot roll. If a custom runtime table cannot be serialized, its preview may fall back to its resource JSON; actual machine drops remain authoritative.

## JEI startup performance

### Botany Pots soil discovery — [#15](https://github.com/rulanup/JDTE/issues/15)

Greenhouse recipe discovery previously checked soil recipes against every registered item for each crop, multiplying the amount of work in large modpacks. Ordinary Botany Pots crops now test the soil ingredients they explicitly declare and resolve matching soil recipes through the public Botany Pots lookup.

When none of those declared ingredients matches, the ordinary crop stops without a full item scan. Custom crop implementations without concrete ingredient data retain the compatibility fallback. This removes the reported exhaustive path; no timing claim is made for the reporter's complete modpack. The older general loading report [#7](https://github.com/rulanup/JDTE/issues/7) still needs its full environment to confirm all remaining causes.

## Advanced Potion Brewer automation — [#12](https://github.com/rulanup/JDTE/issues/12)

- New machines enable external Blaze Powder fuel input by default. Existing saved on/off settings, including the older side-setting format, remain authoritative.
- Fuel keeps automation slot index `4` and accepts access from all six sides or an unspecified side, supporting tools that address slots directly.
- Turning off fuel insertion retains the existing fuel and keeps it visible to inventory queries. Fuel is still not an extraction slot.
- Bulk Blaze Powder input fills the fuel slot without spilling into unrelated ingredient steps. To automate a Strength potion step while fuel input is enabled, place powder in that ingredient slot and lock the recipe first.
- Powder remains an ordinary brewing ingredient when fuel input is disabled or an Energy Brewing Upgrade is installed. That upgrade still disables the fuel slot.
- Built-in Auto I/O uses the same validation as external insertion and respects the configurable guard against fuel supplied by an adjacent AE2 Pattern Provider.

## Time Multitool input and enchantments — [#18](https://github.com/rulanup/JDTE/issues/18)

Short attacks stay on the initial targeted block. Progress on that block continues normally; switching to another block requires holding attack for the configured delay. The default is **250 ms**. Releasing the bound mouse button or keyboard key stops mining and resets the next press. The gate also resets on focus loss, opening a screen, changing worlds, or changing hotbar slots.

The client setting is `jdte.timeMultitool.continuousMiningHoldDelayMillis` in `config/jdte/time-accelerator-local.toml`. It accepts **0–2000 ms**; choose 200 or 300 ms to tune the input, or 0 to allow continuous mining immediately. Edit it from the main-menu configuration or the file. Explicitly enabled JDT Hammer, Tree Feller, and other area abilities retain their existing behavior.

The tool is also added to the vanilla `minecraft:enchantable/mining_loot` eligibility tag for Fortune and Silk Touch enchanted books. Their vanilla mutual exclusion remains in effect.

## Ultimate Portal Gun balance — [#10](https://github.com/rulanup/JDTE/issues/10)

Manual coordinate destinations now use substantially lower Portal Fluid costs:

| Manual destination cost | Previous | pre6 |
| --- | ---: | ---: |
| Same dimension, per block | 1,000 mB | 25 mB |
| Same-dimension maximum | 500,000 mB | 25,000 mB |
| Cross-dimension teleport | 1,000,000 mB | 500 mB |

Distance charges round up to whole mB. The default tank remains **1,000,000 mB (1000 B)**. Quick-added destinations keep JDT pricing, and returning to the previous destination no longer accidentally uses the currently selected manual slot's pricing. FE behavior is unchanged. Configuration descriptions now correctly identify Portal Fluid.

## Documentation and validation

README files, KubeJS guides, developer references, the changelog, and in-game version pages now describe pre6. Extended machine guide coverage is complete, and generated English and Chinese Patchouli pages match their GuideME sources.

Validation for this release includes **502 passing tests, zero failures, and zero skipped tests**, document validation covering **932 language keys, 61 blocks, and 40 guide pages**, and successful JAR/source-JAR builds. Focused coverage includes generator burning, machine NBT restoration, fuel insertion, runtime loot edits, JEI recipe replacement, soil candidates, transmitter lookups, portal costs, and input timing.

Real-client input testing, long-running badpackets integration, and the reporter's complete AE2/SFM/LootJS modpacks have not been exercised end to end. [#14](https://github.com/rulanup/JDTE/issues/14) remains unconfirmed as a JDTE issue because its supplied crash stack points to Torchmaster's Feral Flare Lantern.
