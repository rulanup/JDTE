# JDT Extras 0.6.5.1

Released October 21, 2026. Fixes the Eternal Starlight world-login crash and Fluid Mixers consuming resources without producing fluid.

## Compatibility and installation

| Component | Requirement |
| --- | --- |
| Minecraft | 1.21.1 |
| Mod loader | NeoForge 21.1.216 or newer |
| Just Dire Things | 1.5.7 or newer |
| Java | 21 |

Install `jdte-0.6.5.1.jar` on the client and server. The optional full-grid AE2 addon is `jdte-ae-0.6.5.1.jar`; use matching JDTE and JDTE-AE versions on both sides with AE2 19.2.17 or newer in the 19.x series. The `-sources.jar` files are for development. SHA-256 checksums are included in `SHA256SUMS-0.6.5.1.txt`.

## Eternal Starlight world-login crash — #22

- Fixed mineral survey metadata encoding during player login and datapack reload with Eternal Starlight 0.9.1. JDTE previously encoded structure-avoidance placement filters with plain JSON operations, expanding structure references into a template pool whose fallback references itself and causing `StackOverflowError`.
- Mineral analysis now receives the live server registry context. Named references remain IDs or tags instead of expanding their complete object graphs.
- Missing registry context and excessive inline holder traversal are rejected before stack exhaustion. Each metadata encoding has its own holder traversal budget; direct configured-feature unwrapping also detects repeated objects and bounds its depth.
- Placement metadata is inspected only after finding ore targets. Unsupported metadata skips that estimate while preserving other ore entries and count/height estimates.
- The fix applies to JDTE's survey analysis and preserves Eternal Starlight's world-generation behavior. See [the diagnosis and source evidence](https://github.com/rulanup/JDTE/blob/v0.6.5.1/docs/fixes/issue-22.md) and [issue #22](https://github.com/rulanup/JDTE/issues/22).

## Fluid Mixer output and resource loss

- Fixed the output tank rejecting the machine's own generated fluids while inputs, catalysts and FE were still consumed. This affects both Advanced and Extended Fluid Mixers, including the reported MEKE liquid uranium and liquid silicon fuel recipe.
- The output tank now accepts internal production. External fills through the machine's fluid capability remain restricted to input tanks A and B.
- Normal, parallel and accelerated mixing simulate the complete output batch and store it before consuming resources. If a fill is incomplete, the previous output contents are restored and inputs are retained. Empty outputs, insufficient capacity and incompatible fluid components reject production.
- Added the missing dedicated Auto I/O and AE output route. Input fluids and catalysts use input routes; generated fluid is exported from the output tank.

## 中文说明

### 与永恒星光同装时登录世界崩溃（#22）

- 修复玩家登录和数据包重载时，矿物清单编码结构引用导致无限递归、最终触发 `StackOverflowError` 的问题。
- 使用服务器的实时注册表上下文，保留结构和模板池的引用 ID 或标签，避免内联展开合法的循环引用。
- 注册表上下文缺失、内联 Holder 遍历超限或配置特征重复引用时提前退出；只有确认存在矿物目标后才分析放置条件。
- 无法读取的可选元数据仅跳过该条估算，保留其它矿物与数量、高度信息。永恒星光的世界生成保持原有行为。[完整定位说明](https://github.com/rulanup/JDTE/blob/v0.6.5.1/docs/fixes/issue-22.md)。

### 混合器吞原料、没有流体产物

- 修复输出罐误拒绝机器内部产物的问题，覆盖高级与扩展混合器，包括反馈的 **MEKE 液态铀 + 液态硅 → 液态硅铀燃料** 配方。
- **普通、并行和加速混合**均先确认整批产物能完整存入，再扣除流体原料、催化剂和 FE。存入不完整时恢复原输出罐，保留原料；输出为空、空间不足或流体组件不兼容时不生产。
- 外部流体灌入仍只进入两个输入罐，补齐自动 I/O 与 AE 从专用输出罐导出产物的路径。

主模组和配套可选 JDTE-AE 均更新为 **0.6.5.1**。客户端与服务端请使用匹配版本。

These fixes were compiled and packaged during development. Gameplay with the complete reported ATM10 save and the MEKE fuel setup has not been verified in-game.

开发阶段已编译打包；尚未在完整 ATM10 存档或所反馈的 MEKE 燃料生产环境中进行游戏内验证。
