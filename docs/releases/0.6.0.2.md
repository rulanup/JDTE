# JDT Extras 0.6.0.2

Released September 27, 2026. This is the performance and stability optimization release for the 0.6.0 line, focused on Time Accelerators, for Minecraft 1.21.1, NeoForge 21.1.216+, Just Dire Things 1.5.7+, and Java 21.

## Compatibility and installation

| Component | Requirement |
| --- | --- |
| Minecraft | 1.21.1 |
| Mod loader | NeoForge 21.1.216 or newer |
| Just Dire Things | 1.5.7 or newer |
| Java | 21 |

Install the matching `jdte-0.6.0.2.jar` on the client and server. The optional full-grid addon is `jdte-ae-0.6.0.2.jar`; install matching JDTE and JDTE-AE versions on both sides when using full-grid AE2 acceleration. The `-sources.jar` files are for development and are not placed in the mods folder.

Upgrading from 0.6.0, 0.6.0-fix1, or 0.6.0.1 requires no configuration or world changes. Registry IDs, existing config field names, and config file names are untouched, so worlds, datapacks, and player configs stay fully compatible.

## Highlights

### Time Accelerator Performance Overhaul

- **Zero-overhead idle/unaccelerated state**: `TimeAcceleratorBE` and `AdvancedTimeAcceleratorBE` now override `canRun()` to require Time Fluid and FE energy (unless equipped with a Creative Upgrade). When unpowered, out of fluid, or disabled by redstone, machines immediately deactivate their scheduler state and work queues instead of submitting empty work each tick, eliminating repeated chunk scans and block entity traversals when idle.
- **Machine Target Caching (`MachineTargetCache`)**: Discovered block entity machine targets are now cached per accelerator and refreshed every `timeAcceleratorMachineRefreshInterval` ticks (default 20 ticks / 1 second, configurable 1–1200) or immediately when the configured area changes. This eliminates over 95% of per-tick chunk and block entity iterations. Inactive or removed targets are still validated and pruned dynamically on execution.
- **Filter fast path & BlockState caching**: Accelerators without configured filter items (default denylist mode) now immediately pass blocks in O(1) time without allocating hit results, looking up fake players, or calling `getCloneItemStack`. For configured filters, non-NBT item matching and a local `BlockState` decision cache drastically reduce pick-block overhead during both discovery and batch execution.
- **Visual effect network packet optimization**: Eliminated server-side per-tick entity data updates (`set(REMAINING_TIME)`) in `TimeAcceleratorEffectEntity`. Particle overlay lifetimes are now managed locally on the client and renewed by the server at intervals. Added a new configuration toggle `timeAcceleratorEffectsEnabled` (default `true`) allowing complete suppression of visual effect entities for high-density setups.
- **Packet transmission stability**: Enclosed effect entity broadcast calls in safety guards to prevent unexpected network/disconnect exceptions (`ReportedException: Sending packet`) from interrupting machine ticking or crashing the dedicated server.
