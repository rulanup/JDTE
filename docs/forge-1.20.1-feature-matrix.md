# Forge 1.20.1 feature migration matrix

Reference: JDTE 0.6.5.2 `ccf46472abaf3856fa9eebe0f5ebd25d8f28e859`. Audit started at `020109b`; version stays 0.5.8. This inventory covers **all 120 literal item registrations**, including all entries in the original migration checklist, not just the initial registry delta. The unused `blockItem(name, ...)` helper adds no dynamic registrations.

## Classification and limits

- **V — implemented with behavioral verification:** concrete code and retained tests/runtime evidence for the stated paths. This does not certify every optional backend, recipe pack or long-running workload.
- **U — implemented, unverified:** concrete implementation and wiring, but dedicated behavioral evidence is absent or acceptance coverage remains incomplete. Build/registration alone does not upgrade U to V.
- **P — partial:** known source behavior or integration is missing, even if its core machine works and has tests.
- **N — not implemented:** no item registration/gameplay wiring. Copied textures alone are not implementation.

The machine family and individual upgrade rows are separate: a verified new card does not complete every feature of its host machine. Names come from the pinned English language file. `BE/Menu` and `Model/Language/Recipe` are static presence signals, not proof of working behavior. `Recipe` refers to an exact-name JSON only; source intentionally recipe-less or dynamic recipes are not inferred missing from this flag. JSON contains actual implementation file paths and blockstate presence. Source/Forge API renames and inherited methods are not classified as missing behavior solely from method-name differences.

Current inventory: source **121**, Forge **121**. Status counts: V **115**, U **4**, P **2**, N **0**.

Executed evidence note: the item and fluid receiver families (all three tiers) now run in the `Forge 1.20.1 GameTests` workflow through `ReceiverValidationGameTests` (pull from a real adjacent inventory/tank, exact conservation, save/load survival, energy gate for the powered tier), and `UltimateEssenceConversionGameTests` covers the four-pattern rotation, the oversized-stack round trip and ultimate-card exclusivity. The Fluid Stabilizer family now also has an executed FluidDrop fixture (`FluidStabilizerValidationGameTests`, built from a real loaded JDT recipe) covering recipe application, the area scan, the single-catalyst cost and the FE gate. The two Ultimate cards are **V**: the gate mirrors the 1.21.1 source shape and `UltimateDefaultBranchGameTests` plus a headless real-client run prove their physical effects on default-branch hosts; see [ultimate-card evidence](validation/forge-1.20.1-ultimate-cards/README.md). Closing that gate also removed the only named source-behaviour gap on 24 machine rows, which therefore moved from **P** to **U**: those machines are implemented and wired and the cards now install, but they still have no dedicated per-family acceptance round. The 2 rows that remain **P** are the two greenhouses: their matrix surface is a contract for a companion controller mod (`jdte_matrix`) with no 1.20.1 counterpart, so it is recorded as a real but non-actionable gap rather than dead code. Both are hidden from the creative tab and from JEI (the item list, the greenhouse recipe category, its recipes and its catalysts) while staying registered so existing worlds keep loading. The reason is the gap itself: the machines work, but presenting them as finished content while their only integration path is missing would misrepresent the port. The three time accelerators left that list on 2026-11-20: their named filter-cache gap was real and is now ported with a GameTest, `TimeAccelerationTargetProxy` turned out to be byte-identical to the source, and the remaining "server timing" item is a documented design divergence (this branch runs its own scheduler with execution/scan/pending budgets instead of the source duration-window model), not a missing API. Earlier the same day the Advanced Potion Brewer gained the source coalesced accelerated brewing, and the eight Extended T2 machines passed their operation-parity review with the one real divergence (the source try/catch fallback around `getCloneItemStack`) now ported. The Advanced/Extended fluid senders left that list on 2026-11-20: their client tank-bar question was closed by the minimum-one-pixel row and confirmed in a real headless client; see [tank-bar evidence](validation/forge-1.20.1-fluid-sender/client-tank-bar/README.md). Latest green run: [44511706746](https://github.com/rulanup/JDTE/actions/runs/44511706746) (421/421 tests).

## Rebuild and maintain

Curated behavioral classifications and notes live in `forge-1.20.1-audit-classification.json`; the generated machine-readable inventory is `forge-1.20.1-feature-inventory.json`. Review source and evidence before changing a classification, then run `python scripts/audit_forge_port.py`. Use `--check` to detect stale tables without executing Minecraft or Gradle. This intentionally does not infer completed gameplay from a registered class or count of tests.
