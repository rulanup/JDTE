# 时间加速器并行加速与单次时长配置设计

## 目标

为时间加速器增加两个只能通过服务器/存档配置文件修改的服务器配置项：

1. 可选地跳过全局每 tick 执行上限，使一次调度可以完成范围内全部已发现机器的加速工作。
2. 以秒为单位配置一次提交的加速时长，并让时间流体消耗与该时长严格成正比。

## 权限与配置作用域

- 两个新增配置属于服务器权威配置，不加入现有 `COMMON` 配置文件。
- 使用独立的 NeoForge `SERVER` 配置注册，使服务器加载的值作为唯一运行时来源，并在需要时同步给客户端。
- Dedicated Server 由服主在服务器停止时编辑服务器配置文件；存档级覆盖位于该世界的 `serverconfig` 目录。
- 主菜单或尚未进入存档时，JDTE 自己的配置界面显示并允许编辑这两个字段；这些修改只作为本机单人世界使用的服务器配置，不会改变远程服务器配置。
- 进入单人存档后，两个字段仍显示，但必须置灰且不可保存修改。
- 连接多人服务器后，两个字段仍显示，但必须置灰且不可通过客户端写回服务器配置；服主仍通过服务器配置文件修改。
- 不增加修改这两个值的命令、网络包、方块 GUI 或权限绕过入口。
- 配置文件中的注释和中英文说明必须明确写出：游戏中配置项为只读；服务器服主和单人玩家应在主菜单或游戏外修改，修改后重新启动/重新加载对应服务器配置。

### `timeAcceleratorAccelerateAllMachines`

- 类型：布尔值。
- 默认值：`false`。
- 关闭时，保留现有 `timeAcceleratorMaxExecutionsPerTick` 全局执行预算和目标队列轮询行为。
- 开启时，调度器跳过全局每 tick 执行预算，持续处理当前队列，直到本轮已发现目标的待执行工作完成或目标失效。
- 该设置只表示逻辑上的同轮处理，不创建线程；所有方块实体 ticker 仍在 Minecraft 服务端主线程执行。
- 现有范围、过滤器、有效目标检查、AE2 目标、重叠加速贡献、无效目标清理、每目标批量大小和待执行上限继续生效。
- 配置项的文件注释和语言描述必须明确警告：开启后机器较多时可能造成服务器卡顿、MSPT 升高或短暂无响应。

### `timeAcceleratorAccelerationDurationSeconds`

- 类型：整数。
- 默认值：`1`。
- 合法范围：`1–60` 秒。
- 内部虚拟工作量为：

  `durationSeconds × 20 × effectiveMultiplier`

- 例如有效倍率为 `16`、时长为 `3` 秒时，一次提交为 `960` 个虚拟 tick。
- 同一时长换算用于基础加速、加速管理器和 `accelerateArea()` 参考路径，避免两条执行路径行为不一致。

## 资源消耗

- 时间流体成本按照实际增加的虚拟 tick 数线性增加，即原有单次成本乘以 `durationSeconds × 20`。
- FE 成本也按照实际增加的虚拟 tick 数线性增加，避免延长加速时长后只增加时间流体而不增加能量成本。
- Creative 升级继续免除相应资源消耗。
- 现有 `pendingFluidCost` 小数累积机制继续使用，资源检查和实际扣除必须基于同一份时长换算，不能因整数取整而少扣时间流体。
- 并行模式不按目标数量重复扣除资源；一次时间加速器提交仍只按其配置时长和有效倍率扣除一次资源，和现有“一个加速器一次提交”的成本模型一致。

## 实现边界

### 配置层

- 新建独立的 `TimeAcceleratorServerConfig`，在 `timeAccelerator` 分组中注册两个字段，并通过 `ModConfig.Type.SERVER` 注册专用服务器配置文件。
- 在 `JDTEConfig.Server` 暴露服务器配置值；时间加速器管理器只从服务器配置读取这两个字段，不从客户端或 `COMMON` 值读取。
- 在 `JDTE.java` 注册 `SERVER` 配置，并保留现有 `COMMON` 配置注册不变。
- 在 `JDTEClientMod` 的配置界面过滤器中识别新增 `SERVER` 配置字段：没有活动世界时保持可编辑；存在活动世界或已连接服务器时返回置灰、不可交互的控件。过滤器不影响其他配置。
- 在中英文语言文件中增加名称、描述、主菜单/游戏中只读提示、文件编辑提示和并行模式的卡顿警告；这两个字段始终显示在 JDTE 配置界面中。

### 加速器资源与工作量

- 时间加速器基类提供统一的“单次时长对应虚拟 tick”换算。
- 管理器构造加速上下文时，使用换算后的工作量进行资源检查、资源扣除和目标入队。
- `TimeAcceleratorBE.accelerateArea()` 使用相同工作量，以保留其作为参考/回退实现时的语义一致性。
- `getEffectiveMultiplier()` 仍表示机器倍率，用于现有机器 UI、倍率展示和成本基础；时长只额外扩大一次提交的虚拟工作量。

### 调度层

- 保留关闭并行模式时的现有执行循环，不改变默认行为。
- 并行模式只绕过全局 `timeAcceleratorMaxExecutionsPerTick` 执行预算；每目标 `timeAcceleratorExecutionBatchSize` 仍限制单次 ticker 调用的请求批量，防止单次调用产生不可控的内部循环。
- 队列必须能够在并行模式下继续处理被重新入队的目标，直到本轮目标的待执行工作耗尽、目标失效或被移除。
- 不修改随机刻扫描预算；该预算只约束随机刻目标发现，不是机器方块实体目标的执行预算。

## 错误和边界行为

- 配置值由 `defineInRange` 限制在合法范围；配置文件中的越界值由 NeoForge 配置系统修正/拒绝，运行时不接受小于 1 或大于 60 的时长。
- 时长和倍率相乘时使用足够宽的中间类型，并在传给现有整数成本/批量 API 前进行安全限制，避免配置上限组合导致整数溢出。
- 没有任何有效目标时不扣除资源。
- 资源不足时不入队，也不因并行模式而部分扣除资源。
- Creative 升级仍绕过 FE 和时间流体检查与扣除。
- 并行模式造成的服务器负载属于显式配置选择，配置菜单警告必须同时覆盖中文和英文。

## 验证标准

必须添加或更新自动化测试，覆盖：

1. 并行配置默认关闭，关闭时全局执行上限仍限制执行量。
2. 并行配置开启时，执行量可以超过全局执行上限并处理全部当前目标。
3. `1` 秒和 `60` 秒分别转换为 `20` 和 `1200` 个基础虚拟 tick。
4. 有效倍率参与时长换算，且时间流体和 FE 成本按同一换算比例增加。
5. 资源不足、无有效目标和 Creative 升级的行为保持正确。
6. 配置语言键存在且配置描述包含并行模式的卡顿风险提示。
7. SERVER 配置从服务器配置文件加载；主菜单可编辑，活动世界或多人连接中显示但置灰，客户端不能写回服务器配置。

验证命令至少包括：

```text
./gradlew test
./gradlew compileJava
./gradlew validateDocs
```

## 不在本次范围内

- 不实现真正的多线程方块实体加速。
- 不移除或修改配置项 `timeAcceleratorMaxExecutionsPerTick`；它只在并行模式关闭时生效。
- 不允许在已进入游戏后通过 Mods/Config 菜单、命令或网络包修改两个新增服务器配置；主菜单的单人配置编辑属于本次范围。
- 不扩大时间加速器的范围，不改变过滤器语义，不增加新的机器白名单。
- 不修改配置菜单之外的客户端界面布局。
