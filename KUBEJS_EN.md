# JDTE 0.6.0-pre5: KubeJS and Modpack Content Controls

This guide covers JDTE recipe replacement, recipe disabling, and dynamic JEI recipe switches in KubeJS modpacks. Put KubeJS scripts in the instance's `kubejs/server_scripts/` directory. The JDTE configuration file is `config/jdte/jdte.toml`.

## 1. Disable Dynamic Recipe Generation

Some Greenhouse, Loot Fabricator, and Bio Factory JEI entries are generated by runtime scans. They are not KubeJS `ServerEvents.recipes` recipes, so KubeJS `event.remove()` cannot disable those dynamic enumerations. Use the JDTE configuration instead:

```toml
[jdte.greenhouse]
# Dynamic plant JEI recipes for the Greenhouse and Large Greenhouse
recipeGenerationEnabled = false

[jdte.lootFabricator]
# Dynamic JEI recipes synchronized from server-side loot tables
recipeGenerationEnabled = false

[jdte.bioFactory]
# Dynamic Bio Factory JEI recipes, including Productive Bees integrations
recipeGenerationEnabled = false
```

These switches stop the expensive dynamic JEI enumeration only. They do not remove the machines or data-pack/KubeJS recipes. Restart the client/server after changing configuration; `/reload` is sufficient after changing scripts.

## 2. Disable Blocks, Static Recipes, or KubeJS Recipes

`disabledBlocks` and `disabledRecipes` accept full IDs, short IDs, and directory prefixes. An omitted namespace defaults to `jdte`. A prefix matches itself and its descendants, but not a similar name such as `machine2`.

```toml
[jdte.content]
# Registry IDs remain present for old saves, but disabled blocks are hidden from
# Creative tabs and cannot be newly placed, opened, ticked, or automated.
disabledBlocks = [
  "advanced_item_collector",
  "jdte:time_accelerator",
  "jdte:loot_fabricator"
]

# Filters built-in data recipes and recipes generated by KubeJS.
disabledRecipes = [
  "greenhouse",                                    # jdte:greenhouse/*
  "jdte:bio_factory/cow",                          # one Bio Factory recipe
  "jdte:jei/loot_fabricator/minecraft/zombie"      # all zombie JEI pages
]

# These cover all three Time Accelerator tiers and both Time Freezer tiers.
# Extended Clickers are unaffected.
timeAcceleratorEnabled = false
timeFreezerEnabled = false
```

`disabledRecipes` values are resource recipe IDs, not filesystem paths. For example, `data/jdte/recipe/greenhouse/wheat.json` has the ID `jdte:greenhouse/wheat`. Loot Fabricator dynamic entries use `jdte:jei/loot_fabricator/<namespace>/<path>/<page>`. If the goal is to reduce scanning work, prefer the family's `recipeGenerationEnabled = false` switch.

## 3. Replace a Greenhouse Recipe

In `kubejs/server_scripts/greenhouse.js`, remove the old ID and create a `jdte:greenhouse` custom recipe with the same ID:

```js
ServerEvents.recipes(event => {
  event.remove({ id: 'jdte:greenhouse/wheat' })

  event.custom({
    type: 'jdte:greenhouse',
    seed: { item: 'minecraft:wheat_seeds' },
    outputs: [
      { id: 'minecraft:wheat', count: 2 },
      { id: 'minecraft:wheat_seeds', count: 1 }
    ],
    display_block: 'minecraft:wheat',
    use_loot_table: false,
    growth_work: 4096,
    fluid: 'minecraft:water',
    time_fluid: 100
  }).id('jdte:greenhouse/wheat')
})
```

Field reference:

- `seed`: reusable template input. Use a KubeJS ingredient with `item` or `tag`.
- `outputs`: one or more item stacks. Each entry needs an item `id` and `count`.
- `display_block`: block ID shown in JEI and the client preview.
- `harvest_block`: optional mature block used for harvesting; defaults to `display_block`.
- `use_loot_table`: optional and defaults to `true`; set it to `false` to use only `outputs`.
- `growth_work`: positive integer work required for one harvest.
- `fluid`: optional registered source-fluid ID; defaults to `justdirethings:time_fluid_source`.
- `time_fluid`: fluid amount consumed per harvest; this is an amount, not a fluid ID.

The Greenhouse, Large Greenhouse, and JDTE-Matrix member greenhouses share this recipe type. A greenhouse tank cannot mix fluids. After `/reload`, previously stored fluid can still be extracted, but it only powers recipes that still require that fluid.

## 4. Add a Bio Factory Recipe

Bio Factory recipes use one reusable specimen and up to three unordered material inputs. `count: 0` makes an input a reusable catalyst; a positive count is consumed on each operation.

```js
ServerEvents.recipes(event => {
  event.custom({
    type: 'jdte:bio_factory',
    specimen: { item: 'minecraft:cow_spawn_egg' },
    inputs: [
      { ingredient: { item: 'minecraft:wheat' }, count: 0 }
    ],
    outputs: [],
    output_fluid: 'minecraft:milk',
    output_fluid_amount: 1000,
    process_ticks: 600,
    energy: 1000
  }).id('my_pack:bio_factory/cow_milk')
})
```

Item-output example:

```js
ServerEvents.recipes(event => {
  event.custom({
    type: 'jdte:bio_factory',
    specimen: { item: 'minecraft:bee_spawn_egg' },
    inputs: [
      { ingredient: { tag: 'minecraft:bee_food' }, count: 0 }
    ],
    outputs: [
      { item: { id: 'minecraft:honeycomb', count: 1 }, chance: 1.0 }
    ],
    process_ticks: 600,
    energy: 1000
  }).id('my_pack:bio_factory/bee_honeycomb')
})
```

Optional fluid fields are `process_fluid`/`process_fluid_amount` for a culture or flowering fluid and `output_fluid`/`output_fluid_amount` for a fluid product. A recipe may have item outputs, a fluid output, or both. `chance` is between `0.0` and `1.0` and defaults to `1.0`. The legacy `food`/`food_count` fields are still accepted, but new scripts should use `inputs`.

## 5. The Correct Loot Fabricator Approach

Loot Fabricator has no `jdte:loot_fabricator` data recipe that can be added with `ServerEvents.recipes`. It reads server-side loot tables and synchronizes generated JEI entries to clients. To disable the whole dynamic category:

```toml
[jdte.lootFabricator]
recipeGenerationEnabled = false
```

To hide one mob and all of its output pages instead:

```toml
[jdte.content]
disabledRecipes = [
  "jdte:jei/loot_fabricator/minecraft/ender_dragon"
]
```

Do not use `event.remove({ output: ... })` to remove Loot Fabricator dynamic JEI entries. That event only handles recipes that actually exist as loaded data resources.

## 6. Recommended Script Layout

```text
kubejs/
└─ server_scripts/
   ├─ jdte_greenhouse.js
   ├─ jdte_bio_factory.js
   └─ jdte_recipe_cleanup.js
```

Give custom recipes their own namespace such as `my_pack:`. When replacing a built-in recipe, call `event.remove` first and reuse the original ID. Run `/reload` after editing scripts and check the KubeJS recipe-reload log. If a recipe does not appear, check the custom recipe type, field names, source-fluid validity, and whether `jdte.content.disabledRecipes` matches its ID.
